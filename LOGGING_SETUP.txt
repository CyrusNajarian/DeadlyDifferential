GOOGLE SHEETS LOGGING

The uploaded old ZIP did not include its earlier logging implementation. This package includes a receiver and browser logger that use schemaVersion 2.

To activate the matching receiver:
1. Open the private Google Sheet you want to use.
2. Open Extensions > Apps Script.
3. Replace the code with Google_Sheets_Logger.gs from this package.
4. Run setup and authorize it. This stores the bound spreadsheet ID.
5. Deploy > Manage deployments > Edit your existing web app > New version > Deploy.
   Keep Execute as: Me, Who has access: Anyone.
6. Keep the same deployment URL. If it changes, replace the endpoint in logger.js.
7. Redeploy the site to Netlify, play a test attempt, and verify rows in your Google Sheet.

Layout:
- Attempts: one row per attempt with team, submitted answer counts, visible seconds, and links to detail/summary tabs.
- Attempt N Logs v2: full events for that attempt.
- Attempt N Summary v2: inputs grouped by clue, stage/person, and category, with timing on screen rows.

Existing incompatible overview headers use an Attempts v2 tab; existing tabs are preserved. This receiver does not migrate legacy logs. Duplicate event IDs in an attempt are ignored.

Resetting creates a new attempt ID. Time is recorded only while the page is visible, with periodic checkpoints and navigation/page-exit events. A force-closed browser may lose the final timing interval. Submitted answers retain the original wording.

CONFIRMED AUTOMATIC UPLOADS
The browser now sends each event immediately through /.netlify/functions/log-events. Deploy this repository through Netlify's Git integration so Netlify builds netlify/functions/log-events.js; dragging only static files into Netlify does not deploy the function. No additional packages or credentials are required. The function forwards schemaVersion 2 batches to the existing receiver URL and only confirms delivery when Apps Script returns {ok:true,schemaVersion:2,eventIds:[...]} confirming every event ID in the batch. Redeploy the updated Google_Sheets_Logger.gs once, even if an older receiver was already deployed. The browser retains every event in its local archive, including after confirmation.

Failed requests remain queued and retry every 15 seconds, on reconnection, and when the page reopens. The status beneath the clue distinguishes confirmed sync from pending or failed uploads. Retry log upload retries manually. An HTML/login page, a missing function, a timeout, and receiver errors never mark events as synced.

Older events marked dispatched are replayed once for confirmed delivery. The receiver deduplicates their original event IDs. This can recover retained browser logs from already-reset attempts; it cannot restore answers that were never recorded or whose browser storage was erased. Reopen the same site in the original browser/device to replay its archive. Do not clear browser storage while an upload is pending.

If the status says Google Sheets did not confirm saving, verify the matching receiver deployment using steps 1–6 above. The connected Drive account alone cannot update an Apps Script web-app deployment. After deployment, submit an answer and verify both the confirmed status and the corresponding Sheet row. ?qa=1 deliberately disables uploads.
